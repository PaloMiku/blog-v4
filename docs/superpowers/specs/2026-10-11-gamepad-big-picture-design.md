# 手柄大屏模式设计

**日期：** 2026-10-11

**状态：** 设计方向已确认；本文件供实现前审阅。

## 目标

为博客增加类似 Steam 大屏模式的渐进增强体验：检测到手柄连接后不打断当前页面，用户第一次按下手柄按键后进入专属布局；在首页、文章、归档、游戏、友链和关于页面中提供连续的焦点导航、侧栏折叠、文章滚动与返回操作。

## 设计原则

- 普通鼠标、键盘和触摸用户继续使用现有页面与布局。
- 不新增 Vue 岛或第三方手柄库；交互继续使用 Astro 组件内原生脚本与现有布局状态单例。
- 手柄模式通过属性和 CSS 叠加在现有 DOM 上，避免维护第二套页面路由和内容渲染树。
- 所有可操作目标都保持语义 HTML、键盘可达和可读的 ARIA 状态。
- 模式状态与侧栏、搜索、灯箱状态分离，互不覆盖。

## 用户流程

1. 同一标签页第一次访问时正常加载，手柄模式关闭；后续站内跳转按下文会话规则恢复已启用的模式。
2. 浏览器允许检测到手柄后显示一次轻提示：“手柄已连接，按任意键进入大屏模式”。连接本身不切换布局。部分浏览器需要用户先操作手柄才暴露设备，不能保证物理插入时立即弹提示。
3. 用户第一次按下有效按钮后进入大屏模式；摇杆漂移不触发进入。进入时消耗这次按键，直到松开再按才执行确认或返回，防止首次 A 意外打开文章、首次 B 意外离站。鼠标或键盘仍可使用。
4. 若现有焦点位于可见且可操作的目标，保留它；否则列表页定位第一张文章或入口卡片，阅读页定位正文阅读入口。顶部提供“导航”“目录”（有目录时）、“设置”“退出大屏”按钮。
5. A 确认当前焦点，B 关闭当前层级或返回，LB/RB 在区域或分页之间切换，右摇杆滚动当前滚动容器。
6. 断开手柄时保留当前页面的布局，显示“手柄已断开”，停止轮询；可使用鼠标、键盘或触摸点击退出。重连后重新检测标准映射，松开全部按钮再处理新输入。
7. 页面跳转时清理页面级焦点和输入监听，模式意图保留在标签页会话中。若未来启用 Astro ClientRouter，`astro:before-swap` 只销毁页面控制器，不清空模式意图，`astro:page-load` 再初始化。

## 运行时架构

### 模式与布局状态

现有 `src/lib/layout-state.ts` 继续负责互斥的侧栏、右栏、搜索和灯箱抽屉。大屏模式使用独立的 `src/lib/big-picture-state.ts`，避免把持久模式与抽屉枚举混在一起。

`big-picture-state.ts` 提供：

- `BigPictureMode = 'inactive' | 'active'`；设备连接和提示状态另行记录，避免断开事件覆盖模式
- `getBigPictureState()`、`setBigPictureState()`、`enterBigPicture()`、`exitBigPicture()`
- `subscribeBigPicture()`：订阅者立即收到当前状态
- `bindBigPictureGlobals()`：幂等绑定页面生命周期和退出事件委托

状态变化同步 `document.documentElement[data-big-picture]`，组件样式与焦点层订阅该状态。整页跳转通过 `sessionStorage` 保存 `active` 和 `autoEntrySuppressed`；手动退出设置后者，同一标签页不再自动进入，顶部或常规控制面板仍允许手动进入。关闭标签页结束模式会话。

设置面板提供“首次按键自动进入”开关，默认开启，用 `localStorage` 保存；存储被禁用时退回内存，页面功能正常可用。关闭自动进入只改变后续进入行为，退出使用独立按钮。模式不写入 URL，不保存手柄 id。页面加载时先读取会话意图，设备未重新暴露时显示“按手柄键继续”，不凭旧 index 生成输入。

支持范围由页面声明 `bigPicturePage`，取值为 `home`、`archive`、`games`、`links`、`reading` 或 `off`。首页、归档、友链页面显式传入；兜底内容路由根据 `entry.data.isPost`、游戏条目或关于条目标记识别，兼容文章 permalink，不能仅按 URL 前缀猜测文章。云盘、预览、组件示例和 404 使用 `off`，暂停本页增强但保留会话意图，返回核心页面后恢复。

新增 `src/components/blog/BigPictureShell.astro` 在 `Blog.astro` 中挂载，负责状态提示、顶部动作、底部动态键帽和设置面板；客户端 `<script>` 协调模式、输入、焦点及现有 `layout-state`、`modal`，不承担内容渲染。

### 手柄输入层

新增 `src/lib/gamepad.ts`，只在客户端脚本中导入。它负责：

- 监听 `gamepadconnected` / `gamepaddisconnected`；
- 初始化、页面重新可见和连接事件时读取 `navigator.getGamepads()`；按 `index` 定位并每帧重新获取对象，处理数组空洞及复用 index；
- 将标准按钮和方向输入归一化为 `confirm`、`back`、`previous-region`、`next-region`、`up`、`down`、`left`、`right`、`scroll-up`、`scroll-down`；
- 左摇杆方向触发阈值 0.55、释放阈值 0.35，只取幅度更大的轴；方向键优先于左摇杆，首次移动立即触发，持续按住 350ms 后每 120ms 重复一次；确认、返回和肩键仅按下边沿触发；
- 右摇杆纵轴死区 0.25，滚动速度按超出死区的比例计算，最大 900px/s，按帧时间累积；用立即滚动而非每帧叠加平滑滚动，避免松手仍滑行；
- 从非大屏模式进入时，第一条按钮输入只请求启用模式，不同时发布动作；
- 页面失焦、隐藏、离开、无可用手柄或自动进入被抑制时停止轮询，重新聚焦后读取设备再恢复；未连接时仅保留连接监听，不空跑 rAF。

只对 `mapping === 'standard'` 的设备启用标准映射：按钮 0 确认、1 返回、4/5 肩键、9 打开/关闭设置，12–15 方向键，轴 0/1 左摇杆、3 右摇杆纵向。提示以动作名和通用键帽为主，不通过手柄名字承诺厂商布局兼容。非标准映射显示不支持提示并继续正常浏览。

多手柄时，首个按下按钮的标准手柄成为当前输入来源；只响应一个设备，当前设备断开后允许另一设备通过新按键接管。页面重新获取焦点后，已保持按下的按钮必须先松开；首次进入所用按钮是唯一允许消耗为进入意图的初始样本。

输入模块不查询内容元素、不操作历史记录；通过回调发布语义输入和连接状态，由 Shell 协调进入模式及动作分发。映射和节流纯函数放在 `src/lib/gamepad-input.ts`，保证测试可以脱离 DOM 验证输入。

### 焦点导航层

新增 `src/lib/gamepad-focus.ts`。每个页面通过属性声明焦点目标和区域：

- `data-gamepad-focus`：可被手柄选中的元素；
- `data-gamepad-region`：区域标记，值分别为 `sidebar`、`main`、`aside`、`footer` 或 `overlay`；
- `data-gamepad-scroll`：右摇杆默认滚动容器；
- `data-gamepad-initial-focus`：页面或区域进入时的首个焦点。

焦点管理器维护当前元素、当前区域和上一次有效元素。方向移动仅在当前区域计算：比较元素中心，按方向半平面过滤，优先选择在交叉轴上重叠的候选，再按主轴距离、交叉轴距离排序，同分按 DOM 顺序；没有候选则保留焦点，不跨页或循环。纯几何算法放在 `src/lib/gamepad-navigation.ts`。

进入新区域时恢复该区域上一次仍有效的目标，次选 `data-gamepad-initial-focus`，再选第一项；允许滚动视口之外、但仍属于已展开内容的目标，选中后滚动到安全可见位置。隐藏 Tab 面板、闭合 details 内容、disabled、inert、aria-hidden 祖先和无渲染盒的元素不得入选；轮播中当前不可见的卡片不得入选。

当前焦点调用真实 `focus()` 并加 `.gamepad-focus`；原生链接、按钮、输入框保持原有 Tab 顺序，不把其他全部目标改为 `tabindex="-1"`。正文阅读入口使用临时 `tabindex="-1"`，只供程序聚焦。鼠标或键盘 `focusin` 同步目标，用户接管时不强行把焦点移回手柄目标。

动态列表按 `data-list-key` 或规范化 href 恢复当前目标；失去原目标时保留旧序号对应的邻近项，空列表回到分类/排序按钮。只观察已注册区域的节点增删、hidden 和控件开关，批量刷新一次，焦点类自身变更不得触发刷新循环。客户端创建的新页码按钮需要同步标记。退出模式撤销临时属性并恢复进入前仍可见的焦点。

### 按键语义

- A：链接/按钮/summary 调用原生 `click()`，沿用已有组件事件；文本输入框聚焦，range 或 select 在控件内用方向键改变值并派发原生 input/change。确认触发的外链继续沿用原组件策略，不承诺浏览器一定放行合成点击打开的新窗口。
- B：按层级关闭一层：设置面板 → 最上层搜索/灯箱 modal → 打开的下拉控件 → 侧栏/目录抽屉 → 当前核心页面返回。关闭后回到触发目标。使用 `getModalStack()` 与 `closeModal()`，不能仅修改根属性。动画退场期间阻止再次 B 导致离页。
- 页面返回：在点击同源站内链接前，在标签页存储来源 URL、目标 URL 和当前条目 key；目标与当前路径匹配且来源属于核心页面时返回来源并恢复焦点。缺少来源时，文章返回首页，具体游戏页返回上一级游戏栏目，栏目页返回首页；首页 B 退出大屏模式。禁止仅凭 `history.length` 或 referrer 调用 `history.back()`，以免直接访问的文章把用户送回站外。浏览器自己的后退按钮仍按浏览器规则工作。
- LB/RB：默认循环切换可用区域；只有当前焦点已经在分页控件区域内时才翻上一页/下一页。首页精选轮播区域则切上一张/下一张，焦点随切换更新；不因为页面底部存在分页就全局劫持肩键。动态底部提示必须显示当前实际动作。
- 方向键/左摇杆：移动焦点；连续输入经过节流后重复移动。
- 右摇杆：滚动活动 modal/抽屉中的可滚动容器，否则滚动页面的 `document.scrollingElement`。现有正文不是独立滚动盒，不能对 article 调用 scrollBy 后宣称已完成滚动。滚动不强行重新聚焦或拉回旧焦点。
- 菜单键（标准按钮 9）：打开/关闭设置；页面同时提供可聚焦的“退出大屏”按钮。

模态弹层打开时，焦点目标和 LB/RB 均限制在最上层弹层内；背景焦点不可达。搜索使用现有输入框和结果列表；本期不实现屏幕键盘，输入关键词依赖物理键盘或系统输入方式，返回、搜索结果和关闭可由手柄操作。评论区提供可聚焦的入口，文本编辑使用现有输入方式，不保证第三方评论编辑器的全部控件纯手柄可用。

## 布局与视觉

新增 `src/styles/big-picture.css`，由 `src/styles/index.css` 最后引入，所有规则以 `:root[data-big-picture]` 为入口。

- 保留 `Blog.astro` 中 `#blog-root`、main、sidebar 和 aside 的结构，在模式选择器下改写 grid；顶部状态区和底部提示为常驻 Shell，页面预留空间，焦点滚动不得被两者遮挡。
- 大于 1080px：首页、归档和游戏入口使用左导航、中间内容、右侧信息；右栏仅在页面已有内容时显示，不虚构阅读时长或统计。首页文章列表两列卡片，归档保留年份与条目分组，游戏保持现有 LinkBanner 图片。769–1080px 默认左导航与内容两列，右栏抽屉；不大于 768px 默认内容单列，两侧均为抽屉，包含 Steam Deck 常见的 1280×800 视口验证。
- 文章页、具体游戏档案和关于页默认收起左右栏，正文居中，列宽上限 860px，字号约 18–20px、行高 1.8；顶部“导航”“目录”按钮可打开复用的侧栏抽屉。关闭抽屉后归还焦点。友链页使用内容列表布局，不因正文存在而自动判为阅读态。
- 搜索、灯箱和标签页沿用现有 modal、tab 和 layout 状态，只增加手柄焦点标记与视觉状态。
- 沿用已确认草图的深蓝背景、蓝色焦点框和清晰的大字号控件；在 `data-big-picture` 下用专属 --bp-* 令牌覆盖主题所需颜色，不修改现有 dark/light 存储偏好。焦点使用 3px 描边，卡片最多上移 2px；正文内链接只描边不位移，`prefers-reduced-motion` 关闭位移和平滑定位。退出立即恢复原主题。
- 非大屏模式不命中这些选择器。CSS 随共享布局构建，不宣称完全零字节；无手柄时不启动轮询或焦点观察。新增输入模块不导入包含 Temporal 的 `app-config` 客户端运行时，Shell frontmatter 可以在构建期取必要配置。

## 页面接入点

### 首页

`src/pages/index.astro`：侧栏导航、搜索入口、精选 Slide、文章卡片、排序控件、分类控件和分页按钮加入焦点/区域属性。客户端列表重排后调用焦点管理器的 `refresh()`，保留当前文章 key。

### 文章页

`src/pages/[...slug].astro`：目录链接、PostSurround、已显示的系列文章、评论入口、正文中已有按钮/标签页/折叠组件加入属性。进入阅读态时聚焦正文阅读入口；B 键按来源和兜底规则返回。`compat.hideCollectionBlock` 保持现状，不为手柄模式重新开启隐藏的系列区块。

### 归档页

`src/pages/archive.astro`：年份导航、排序/分类控件、归档条目加入区域标记。保留现有归档列表结构，不新增当前页面没有的分页。列表变更后按条目路径恢复焦点。

### 游戏页

游戏内容由内容集合和 `LinkBanner` 组件组成；为 `/games`、`/games/galgames` 以及具体游戏页的入口卡片、系列导航和文章前后篇提供同一套属性。

### 友链页

`src/pages/link.astro`：友链卡片、现有 Tab 按钮和评论入口加入焦点标记；切换 Tab 后当前按钮保持焦点，方向向下进入新面板首项。申请友链内容沿用当前说明页，不新增申请表单或分页。

### 关于页

关于页中的 `ProjectGroup`、外部链接和页内标题锚点加入区域标记。外部链接仍由现有 `UtilLink` 处理，不改变打开策略。

## 无障碍与错误处理

- 折叠侧栏用 `aria-hidden` 与 `inert`，展开时恢复；退出模式根据当前视口重算现有抽屉状态。`BlogAside` 的 media-query 监听须统一走同一可见性函数，避免 resize 把折叠栏重新暴露；不能让 Shell 和 Aside 分别写相反的状态。
- 无标准映射、按钮数量不足或游戏板读取失败时只停用手柄增强，不影响页面和键盘操作。
- 输入事件不在输入框、文本域或可编辑区域上抢占键盘事件；手柄 A 仍可确认当前控件。
- API 不存在、非安全上下文、浏览器策略禁止读取或存储异常时退回常规页面和可用的手动入口，显示可读提示；服务端模块顶层不得访问 window/document/navigator。
- 页面销毁和 ClientRouter swap 时取消 rAF、移除事件监听、清除焦点类和临时属性；重新绑定必须幂等，无重复事件或多条 rAF 循环。

## 验证策略

新增纯逻辑测试：

- `tests/gamepad.test.mjs`：标准按钮归一化、摇杆阈值/滞回、350/120ms 重复节流、首次输入只进入、多手柄接管和帧时间滚动；
- `tests/gamepad-focus.test.mjs`：空间候选排序、区域循环、无候选、初始焦点、列表重排 key 恢复及可见性过滤；
- `tests/big-picture.test.mjs`：独立模式和抽屉状态、会话续接、关闭自动进入、手动退出抑制、断开/重连，以及返回层级和同源兜底。

扩展 `scripts/interaction-check.mjs` 的真实浏览器检查：

- 在页面脚本加载前，用测试脚本替换 navigator.getGamepads 并发送连接/断开事件，提供真实 controller 状态更新；测试夹具只存在于检查脚本，不向生产页面暴露调试入口，不以手写根属性代替输入链路验证；
- 连接时无布局切换，首次 A 只进入，松开再按才打开目标，方向按住节流可观察；
- 首页、实际文章、归档、游戏索引/子页、友链、关于都有可达目标；
- 当前焦点只有一个，方向移动后焦点可观察地改变；
- A 触发链接/按钮，B 关闭搜索或恢复上一页面；
- 文章阅读态隐藏侧栏并保持正文可滚动；
- 首页列表重排/翻页、归档排序、友链 Tab、轮播切换、搜索结果、灯箱返回不丢焦点，不选中隐藏内容；
- 整页跳转、刷新、浏览器后退、手动退出、设置关闭自动进入、后台/前台和重连符合会话规则；
- 大屏与常规两种模式分别检查 1600×1000、1280×800、800×600、390×844；字体放大、reduced-motion、Tab 顺序和弹层范围仍可用；
- 普通模式下不存在 `data-big-picture`，现有交互断言继续通过。

实现完成后运行 `pnpm test`、`pnpm typecheck`、`pnpm lint` 和 `pnpm accept`（内含 build），复用同一构建产物单独运行 `pnpm interaction-check`。新增静态门禁时必须接入 accept 并注入缺陷验证红绿，浏览器交互检查继续单跑。只扫描属性不能作为功能通过依据。

真实设备至少测一款标准映射手柄，并记录浏览器、系统、连接方式；Steam Deck 与 Xbox/DualSense 列入实机覆盖目标，未连接实机时明确标为未测，不因标准映射模拟通过就声明全部兼容。Gamepad API 规范只描述浏览器输入接口，不保证 Steam Input 在每种浏览器环境中暴露同样设备。

## 实施阶段

1. 输入与状态：纯逻辑测试、按键归一化、会话状态、设备生命周期和 Shell 进入/退出。
2. 导航与动作：空间焦点、区域切换、modal/抽屉/控件作用域、返回策略和滚动。
3. 布局与页面：模式令牌、响应式 Shell、列表/阅读变体、六类页面及动态节点标记。
4. 验证与交付：模拟输入浏览器检查、常规模式回归、现有门禁和实机记录。

后续实现计划按此依赖顺序逐项拆解；本文件只落设计与验收规则，不修改生产功能。

## 技术依据

- W3C《Gamepad》：安全上下文、standard mapping 与输入布局。参考地址：`https://www.w3.org/TR/gamepad/`。
- MDN《Using the Gamepad API》：已连接设备可能在首次操作后才发送连接事件；Firefox 需要可见页面中的手柄操作后才暴露设备。参考地址：`https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API`。
- 核对日期：2026-10-11。这些浏览器限制影响连接提示时机，不改变“首次按钮操作才进入”的产品规则。
